# 准备检查

## 目标

在阅读业务材料前，确认逆向对象、基线、读取许可、用途和输出边界都已经明确，避免在错误
范围内生成事实。

## 在流程中的位置

本文件属于阶段 A 之前的准备门，不是阶段 A 的阅读步骤。只有本检查通过，阶段 A 才能读取
允许的业务材料；本检查本身不寻找入口、不生成模块，也不写入现实资料。

## 检查项目

### 1. 项目和基线

- 目标项目根目录已确认；
- 当前工作树、分支和修改前基线已记录；
- 现实资料将在目标项目自己的隔离位置中形成；
- 未提交文件和被忽略文件不会被当作正式交接依据。

准备检查的机器交接必须形成 `reverse_work_contract`，并绑定项目标识、基线、来源单元、来源角色、
模板包摘要、三个隔离输出根和权限边界。没有 Work Contract，不能进入阶段 A。

### 2. 逆向目标

必须能够回答：

1. 本轮观察哪个项目或功能范围；
2. 本轮用途是什么；
3. 优先从哪类稳定入口开始；
4. 需要哪些事实维度；
5. 是否只做观察、记录、建模和验证，不做业务修复。

如果这些问题没有答案，先输出范围锁定摘要，不直接阅读全仓库。

### 3. 读取许可

- 当前读取契约已列出允许的来源单元；
- 每个来源单元的来源角色已明确；
- 项目清单和读取许可没有冲突；
- 未获许可的路径不会被读取为当前输入；
- 需要扩大范围时，先修订读取契约。

### 4. 目标项目资料

如果目标项目已有 `specs/10_reality/00_profile.yaml` 或等价资料入口：

- 读取目标项目自己的资料契约；
- 确认业务域和资料槽位；
- 不复制 Maglev 自身的业务域、资料页或事实。

如果没有，记录为尚未建立资料契约，并在同一候选提交中建立项目自己的最小入口。

### 5. 输出隔离

- 人读产物目录已确定；
- 机器证据目录已确定；
- 目标 Reality 根目录已确定；
- 两个目录互不包含；
- 三个输出根的职责不混用：人读目录不承载机器凭据，机器目录不承载最终 Reality 页面；
- Pack 只能通过 manifest 声明项目级入口页面的来源资产和 `target_path`，不能由目录名称推导输出路径；
- 产物不写入被忽略的临时候选目录；
- 业务代码、测试、数据和运行状态不在本轮修改范围内。

### 6. 权限边界

- `static_read` 必须为 `true`；
- `runtime_read`、`business_write`、`reality_write` 和 `project_execution` 在本轮必须为 `false`；
- `material_reduction_tools` 在语义阶段必须为 `false`；
- `script_execution` 可以为 `true`，但只允许执行既有工作流已登记且职责不变的脚本，不能据此
  新增脚本、缩窄语义材料或决定模块/边界；
- 如果工作流需要运行时采集、业务写入或 Reality 写回，必须结束当前 Work Contract，重新收敛
  对应权限范围；新增脚本或改变既有职责则先补机制说明。

## 通过条件

全部检查通过后，输出：

```text
[准备检查通过]
- 项目和基线：已锁定
- 读取许可：已锁定
- 目标用途：已明确
- 输出隔离：已确认
- Work Contract：已形成并绑定模板包摘要
- 业务修改：禁止
```

任一项不满足时，说明缺失项并停止，不用扫描结果或目录数量绕过准备检查。
