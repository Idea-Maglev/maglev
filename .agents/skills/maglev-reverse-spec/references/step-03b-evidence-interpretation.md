# 证据解释

## 目标

说明现有材料能支持什么、不能支持什么，把推断、未知和阻断项保留在账本中，不把解释
伪装成设计意图。

## 在流程中的位置

本文件属于阶段 B 的事实解释。它只解释已接受入口、调用链和数据结构中的证据信号，不重新
判断模块、不替用户裁决边界，也不把推断提升为事实。

## 可解释信号

在调用链、数据结构和状态变化中关注：

- 固定数值和固定字符串；
- 复杂校验和异常分支；
- 幂等、防重、锁、重试、熔断和补偿；
- 具有业务含义的命名；
- 注释、配置和测试对语义的补充。

这些信号只能提出有边界的解释，不能单独构成模块或业务规则。

## 记录方式

```markdown
## 证据信号

- 信号：`<代码或配置片段>`
  - 解释：[INFERENCE] <由当前证据推导出的含义>
  - 依据：<相对路径#锚点>

## 未知与阻断

- [UNKNOWN] <当前无法确认的含义>
- [BLOCKED] <因许可、访问或基线无法确认的内容>
```

## 必须保留的缺口

- 关键分支存在但结果无法确认；
- 同一概念在不同层的含义不一致；
- 状态值、枚举值或策略常量来源不明；
- 运行、权限、依赖或提交边界缺失。

解释结果只能作为现实资料的证据边界，不能生成需求、设计、评分或过程队列。
