# 现实资料投影

## 目标

把已完成边界审阅和事实核对的内容，写入目标项目自己的现实资料结构，形成可提交、可检出、
可由独立验证方核对的结果。

## 在流程中的位置

本文件属于阶段 B 的现实资料写入。它只消费阶段 A 已接受的边界和阶段 B 已核对的事实，
不生成语义模块，不重新判断业务归属。

## 前置条件

- 读取范围、基线和用途已经锁定；
- 模块边界已经经过人工审阅；
- 后置结构问题已经处理；
- 事实、推断、未知和阻断已经分开；
- 目标项目的资料契约已经读取，或已决定建立项目自己的最小资料入口；
- 业务代码、测试、数据和运行状态没有被逆向过程修改。

## 写入顺序

1. 读取目标项目自己的现实资料入口和业务域登记；
2. 确认分析模块、来源单元和业务域三者分别记录；
3. 将已核对事实映射到目标项目规定的业务域和资料槽位；
4. 保留既有事实，不覆盖未经核对的内容；
5. 把未知、阻断和证据边界写清楚；
6. 将页面、资料入口和已提交证据一起纳入候选提交。

如果只能证明技术来源而不能证明业务归属，保留在来源地图或未归类账本，不建立新的业务域。

## 目录与页面约束

目录、页面标识和资料槽位由目标项目自己的资料契约及其指定模板包决定。逆向能力不要求
所有项目采用相同的业务域骨架，也不把模板包中的示例目录变成固定输出。

事实正文只能写入目标项目契约规定的资料槽位，并登记到目标项目自己的资料入口。不得把
`module_slug`、`source_unit` 或分析批次名直接变成业务域目录。

## 页面内容约束

写入页面时遵循目标项目资料契约和模板包页面契约；页面内容必须能回查当前结论、范围、事实
类型、证据边界、相对路径和锚点，以及未知、阻断和适用维度状态。上述是事实写入的核对项，
不是逆向能力另设的页面模板。

不得把需求、设计、计划、评分或过程队列写入现实资料。

## 投影交接

候选提交至少要能提供：

```yaml
projection:
  base_commit: <修改前基线>
  candidate_commit: <候选提交>
  reality_digest: <完整现实资料摘要>
  change_digest: <本次变化摘要>
  intended_use: <本轮用途>
```

本地分析缓存不属于交接输入，不能替代候选提交。
