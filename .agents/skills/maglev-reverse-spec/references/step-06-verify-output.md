# 独立验证与准入

## 目标

由独立验证方检出同一候选提交，按本轮使用的模板包重新核对流程、页面、逐模块质量、完整现实资料
和本次变化；准入只确认已经验证的提交，不在验证后另写一份资料。

## 在流程中的位置

本文件属于阶段 B 的最后一步。它消费阶段 B 中间复验记录，但必须在独立上下文中重新核对模板包
约束和最终结果；不重新生成模块，也不替代阶段 A 的语义审阅。

## 前置条件

- 现实资料已经写入目标项目自己的位置；
- 模板、流程和逐模块质量中间复验已经完成，且没有未处理的 `rework_required` 或 `blocked`；
- 候选提交已经形成且工作树干净；
- 已记录修改前基线；
- 证据已经随候选提交可回查；
- 业务代码、测试、数据和运行状态没有被逆向过程修改。
- Gate A 已绑定模块地图、依赖顺序、公共内容和未归类项；
- Gate B 已绑定项目级入口页面和首个模块纵切片，且每道门最多只发生一次受控返工；

如果不能形成可检出的候选提交，只能交付待提交变化和阻断交接，不得宣告通过。

## 生成投影描述

以下命令只能在独立验证完成后使用，不能用来启动阶段 A、替代中间复验或判断模块质量。

如果目标项目使用共享准入入口，可以使用以下命令生成完整投影描述：

```bash
./scripts/maglev-python .agents/skills/_internal/reality-admission/scripts/reality_admission.py \
  --reality-root specs/10_reality \
  --base-ref <修改前提交> \
  --candidate-ref HEAD \
  --intended-use <本轮用途> \
  --json
```

投影描述至少绑定：

- 修改前基线；
- 候选提交；
- 完整现实资料摘要；
- 本次变化摘要；
- 本轮用途。

## 独立验证

独立验证方必须：

1. 检出同一候选提交；
2. 读取同一 Work Contract、模块地图、Gate A/B 记录、模板登记入口、登记清单、方法论、适用
   页面契约、正向示例和模板审阅项；
3. 读取中间复验记录，核对其模板包摘要、选定页面、流程结论和逐模块结论；
4. 按模板页面契约重新检查最终页面是否回答专属读者问题、使用正确来源角色并保留适用性分支；
5. 逐个检查每个已生成模块的目标、稳定入口、边界、依赖、来源角色、证据、未知和阻断；
6. 检查模板包声明的项目级入口页面是否按 `target_path` 直接落在目标 Reality 根目录，且没有生成未声明的输出容器；
7. 检查流程是否遵守“边界裁决后才事实核对、事实核对后才写入”的顺序；
8. 核对每条关键事实的证据；
9. 检查推断、未知和阻断是否被正确保留；
10. 分别给出 structure、content、confidence 三层结论，不以总分或结构通过替代内容与置信度；
11. UIUX/前端适用时，核对用户任务、路由/入口、视图/组件、状态、前端源文件和 API/Store/
    数据连接是否有具体证据；
12. 检查既有资料是否冲突、重复或失效；
13. 检查本轮是否误改业务实现；
14. 按本轮用途完成解释、定位和核对。

独立验证结果至少要分别给出 structure、content、confidence 三层，以及流程、模板消费、逐模块
质量和完整资料的结论。结论是可继续、需返工或阻断，不得用总分代替逐项问题。结果必须符合
`reverse_review_result` 结构，并绑定 `candidate_commit`、baseline、Module Map、两个 Gate、
模板包和最终包摘要。

验证结果必须绑定模板包标识和摘要、中间复验记录、候选提交、完整现实资料摘要和本次变化摘要。
如果运行载体使用 `validation-result.json`，上述模板与中间复验信息应作为同一结果的附加结构传递；
不能只传一个 `pass`。

## 准入

准入脚本不读取模板包，也不判断模块生成质量。它只在独立验证已经完成后，检查提交、工作树状态、
摘要、证据可见性和验证结果绑定是否仍然一致。准入脚本对页面内容不做结构性门禁：它不要求
特定章节、标题或措辞，占位符类残留只产生非阻断提示；页面结构问题一律回到本轮模板包
对照反思修复，禁止改写内容去拟合脚本检查项。

共享准入入口重新计算当前提交、完整现实资料摘要和变化摘要。验证结果可以通过智能体的
结构化返回值传递；只有宿主项目确有需要时才写成文件：

```bash
cat validation-result.json | \
./scripts/maglev-python .agents/skills/_internal/reality-admission/scripts/reality_admission.py \
  --reality-root specs/10_reality \
  --base-ref <修改前提交> \
  --candidate-ref HEAD \
  --intended-use <本轮用途> \
  --validation-result - \
  --accept \
  --json
```

准入通过必须同时满足：

- 当前提交与独立验证方一致；
- 完整现实资料和变化摘要没有变化；
- 独立验证结果已经确认资料契约、结构、内容和置信度通过；
- 验证结果通过且没有冲突或阻断缺口。

没有现实资料变化时，结果为 `no_change`。

只有 `accepted` 或 `no_change` 才能收口；否则交付阻断原因和下一责任点。
