# 模板、流程和模块质量复验

## 目标

在 Gate A 的边界裁决之后、事实核对和现实资料写入之前，独立复验本轮生成结果是否：

- 按规定顺序完成；
- 使用了登记入口指定的模板包；
- 按页面契约组织了适用页面；
- 逐模块保留了目标、入口、边界和证据；
- 正确表达了未知、阻断、不适用、公共内容和未归类项。

这一步只输出复验问题和是否可以继续，不重新生成模块、不替用户裁决边界，也不把事实质量
压缩成分数。它不替代 Gate B：Gate B 必须先审阅项目级入口页面和第一个模块纵切片，再允许剩余模块按
依赖批次生成。

复验应由未参与本轮页面生成的智能体或验证者执行；如果只能由同一智能体继续处理，必须在
新的独立阅读上下文中重新读取模板和原始来源，不能只依据自己的生成记录自我通过。

## 在流程中的位置

本复验属于阶段 B 的中间门禁：

```mermaid
flowchart LR
  A[Gate A 边界与依赖裁决] --> B[后置结构校验]
  B --> C[项目级入口页面与首个模块纵切片]
  C --> D[Gate B 内容、UIUX、证据]
  D --> E[依赖批次逐模块生成]
  E --> F[模板、流程和模块质量复验]
  F --> G[事实核对与适用维度]
  G --> H[现实资料写入]
  H --> I[完整资料对抗审查]
  I --> J[独立验证与准入]
```

复验不写入目标项目现实资料，也不运行项目、网络或业务代码。

## 输入

- 阶段 A 语义审阅包；
- Gate A 边界裁决、公共内容、未归类账本和依赖顺序；
- 读取契约、基线、来源地图和来源角色；
- `templates/reality-packs/registry.yaml` 解析出的登记清单；
- 登记清单声明的模板包、方法论、页面契约、正向示例和模板审阅项；
- 后置结构校验问题项及处理结果；
- 目标项目自己的资料契约（如果已有）。

登记入口、登记清单、页面契约或来源真相无法确认时，复验直接阻断。

## Gate B 前置纵切片

Gate B 不是整包目录检查，而是一次有范围的人工内容门。进入 Gate B 前必须完成：

- 模板包声明的项目级入口页面按 `materialization` 和 `target_path` 直接物化到目标 Reality 根目录；
- 依赖顺序中的第一个模块已生成最小纵切片；
- 纵切片至少覆盖能力目标、稳定入口、UIUX/前端实现边界、一个实现/接口或数据事实、
  一个验证事实、来源定位和 unknown/blocked；
- 页面适用性已经按 `required`、`conditional` 或 `not_applicable` 记录；
- 所有页面和 Claim 绑定当前 baseline、owner page 和深挖入口。

Gate B 人工只裁决是否继续、需要哪类内容返工以及是否阻断，不逐页代写。每个 Gate B 最多允许
一次受控返工；返工后仍不能满足最低覆盖时必须阻断或回到模板/读取契约，而不是降低页面要求。

## 复验顺序

### 一、流程是否正确

逐项核对：

- 是否先锁定项目、基线、读取许可、用途和输出隔离；
- 是否只阅读获准的一手静态材料；
- 是否从页面、路由、接口资源、任务、命令、软件开发工具包、事件或数据生命周期等稳定入口开始；
- 是否没有使用候选图、扫描结果、目录数量、历史产物或失败产物决定模块；
- 是否把 `intent`、`implementation`、`verification` 分开使用；
- 是否先生成语义草稿，再进行人工边界裁决；
- 是否保留公共内容和未归类项；
- 是否没有在阶段 A 写入现实资料或做事实准入；
- 阶段 A 的交接是否足以支撑后续事实核对。

发现流程顺序错误时，不能靠补一段说明放行，应退回对应步骤重新产生结果。

### 二、模板是否真正被使用

按唯一消费链逐项回查：

```mermaid
flowchart LR
  A[模板登记入口] --> B[登记清单]
  B --> C[资产标识和公开路径]
  C --> D[页面映射]
  D --> E[方法论、页面契约、正向示例和模板审阅项]
```

逐个检查本轮实际生成的页面：

- 页面标识和归属是否来自登记清单；
- 页面是否回答契约声明的专属读者问题；
- 页面结构是否使用契约声明的落地结构，而不是逆向能力自造的固定结构；
- 页面是否只使用契约允许的来源角色；
- 是否阅读并参考了该页的正向示例和模板审阅项；
- 适用但缺证据的页面是否保留 `[UNKNOWN]` 或 `[BLOCKED]`；
- 不适用页面是否只记录 `not_applicable`、依据和落地位置，没有生成空页；
- 是否没有用其他页面、通用提示语或模块来源表填充本页义务；
- 页面之间的 owner page、深挖链接和回查路径是否可复核。

模板包只决定页面问题和结构，不决定模块边界，也不把示例内容变成项目事实。

### 三、逐模块检查生成质量

每个已裁决模块必须单独给出结论，不以模块数量、文件数量或整体印象代替检查。

至少核对：

- 是否有独立且可解释的业务目标、责任、对象、流程、状态、权限或接口责任；
- 是否有稳定入口和相对路径证据；
- 是否明确哪些内容来自 `intent`、哪些来自 `implementation`、哪些来自 `verification`；
- 是否只记录了支撑当前边界所需的实现线索，没有把技术目录直接当成业务边界；
- 是否表达了直接依赖、跨模块依赖和公共内容依据；
- 是否把无法归属的内容放入未归类账本；
- 是否保留证据不足、来源冲突和缺少测试的未知或阻断；
- 适用页面是否都有具体内容、具体缺口或明确不适用依据；
- 页面是否能让读者继续定位入口、实现、数据、接口或验证，而不是只看到摘要；
- 是否存在把需求当实现、把测试当生产行为、把推断当事实的越级表达。
- UIUX/前端适用时，是否同时记录用户任务、入口/路由、视图/组件、状态、前端源文件和
  API/Store/数据连接；不能只写页面名称或视觉描述。

“通过”只表示当前结果可以进入下一步事实核对，不表示模块事实已经完成或现实资料可以准入。

### 四、检查跨模块关系和未归类内容

- 公共内容必须列出涉及模块、直接依赖和证据；
- 合并模块必须有真实的跨模块业务关系；
- 拆分模块必须有明确的目标、对象、流程、状态、权限或接口边界；
- 无法安全归属的内容必须保留在未归类账本；
- 不得通过新增“其他”模块消除未决问题；
- 不得因模板页面数量不足而强行扩大模块边界。

## 结论和处理

复验结果分为：

- `pass`：流程、模板消费和逐模块检查没有阻断问题，可以进入事实核对；
- `rework_required`：需要重新生成页面、修正流程记录或回到阶段 A 重新审阅；
- `blocked`：模板、读取许可、基线、来源真相或关键证据无法确认。

处理方向：

| 问题类型 | 返回位置 |
| --- | --- |
| 读取许可、基线或模板真相 | 准备阶段 |
| 模块边界、公共内容或未归类项 | 阶段 A 和人工边界审阅 |
| 页面契约、适用性或页面结构 | 模板消费与页面生成 |
| 来源角色、证据或具体事实 | 阶段 B 事实核对 |
| 仅提交、摘要或候选提交漂移 | 最终准入门禁 |

问题未处理前不得进入事实核对或现实资料写入。复验不调用提交准入脚本，也不以脚本通过代替本复验。

```yaml
    status: pass|rework_required|blocked

```

这里的记录是流程证据，不是新的 Reality 页面模板。
