# 静态证据地图

## 目标

在读取契约允许的范围内，确认有哪些一手材料可读、材料分别承担什么来源角色，以及每份材料
如何回查。这里输出的是来源覆盖和定位种子，不是入口地图、模块列表或候选排序。

## 直接阅读顺序

1. 需求、产品目标和用户任务；
2. 页面、路由、命令注册、任务注册、事件订阅和接口入口等材料；
3. 请求、响应、事件载荷和类型定义；
4. 数据模型、迁移和表结构；
5. 配置、环境变量和开关；
6. 与入口直接相关的测试和断言。

测试仍然只说明验证依据，不能替代目标意图或当前实现。

## 证据隔离

`.agents/`、`.maglev/` 以及由 Maglev 生成的导航资料默认只用于定位，不作为业务事实来源。
只有在已经核对其生成范围、目标项目和来源指纹时，才可以把其中的路径当作导航线索继续回查
一手材料。

## 记录格式

每个来源单元至少记录：

```yaml
source_units:
  - unit_id: <来源单元>
    relative_path: <相对路径>
    roles: [intent | implementation | verification]
    evidence_refs:
      - <相对路径或基线提交>
```

## 明确禁止

- 不按目录、包名、文件数量、词频或相似度生成模块；
- 不把来源单元直接变成业务域；
- 不在此处命名模块或裁决入口归属；
- 不读取未获许可的路径；
- 不使用历史资料、失败产物或运行时结果补当前静态事实。

## 输出

至少输出：

- 来源单元及其来源角色；
- 可读材料、缺失材料和阻断材料；
- 关键文件和锚点定位；
- 每类来源的覆盖和缺口；
- 下一步应建立的入口地图。

下一步由 `step-01-project-map.md` 建立入口与功能地图，再交给阶段 A 总协议继续语义审阅；
本文件不进入自动候选生成。
