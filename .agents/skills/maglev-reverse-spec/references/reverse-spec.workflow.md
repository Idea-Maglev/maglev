# 逆向现状重建工作流

本文件定义从项目准备到现实资料准入的唯一工作顺序。它的目标是恢复当前事实，不是先
猜出一组模块，也不是用工具输出替代人的语义判断。阶段 A 负责“直接阅读、形成模块地图和
语义审阅包、完成 Gate A”；阶段 B 负责“首个纵切片、Gate B、依赖批次生成、事实核对和准入”。
其他入口分析文件是阶段 A 的辅助步骤，不是与阶段 A 并列的流程。

## 文件之间的关系

- `SKILL.md`：定义何时进入本能力、阶段门禁和不可越过的边界；
- 本文件：定义唯一顺序、阶段触发、退出和交接；
- `stage-a-agent-first.md`：定义阶段 A 的直接阅读、模块地图、语义草稿和 Gate A；
- `stage-b-intermediate-review.md`：定义写入前的模板、流程和逐模块质量复验；
- `step-01-*`、`step-02-page-analysis.md`：只补充阶段 A 的入口定位和页面事实；
- `step-02b-*`、`step-03-*`、`step-04-*`、`wrapper-04-*`、`step-06-*`：只补充阶段 B 的
  事实、投影、审查和准入。

下层文件不得重新定义上层文件已经确定的触发条件、阶段顺序或职责边界。

## 各部分职责

| 部分 | 负责 | 不负责 |
| --- | --- | --- | --- |
| 准备检查 | 确认目标、基线、读取许可、用途和输出隔离 | 生成入口、模块或事实 |
| 阶段 A 总协议 | 组织直接阅读、模块地图、依赖顺序、语义草稿和 Gate A | 写入现实资料、做事实准入 |
| 阶段 A 辅助步骤 | 按入口形态提供来源定位、入口地图、入口深入分析和页面事实 | 决定模块边界、公共内容或业务归属 |
| 模板包 | 提供页面契约、方法论、正向示例和审阅项；由智能体按适用页面消费 | 提供项目事实或决定业务边界 |
| 项目适配说明 | 提供项目根目录、基线、读取清单、模板包和输出隔离 | 生成模块、拆分合并模块或决定归属 |
| 阶段 B 后置校验 | 检查契约、路径、来源角色、结构、链接和隔离 | 重写语义或重新判断边界 |
| 阶段 B 中间复验 | 按模板复验流程、页面消费和逐模块生成质量 | 用分数替代判断、重新生成模块或替用户裁决边界 |
| 阶段 B 事实与投影 | 消费已审边界，补齐当前事实并写入目标项目 | 消费历史候选或未审草稿 |
| 阶段 B 独立验证与准入 | 核对完整结果和变化范围，确认是否可以收口 | 代替生产者生成内容 |

## 唯一主链

```mermaid
flowchart LR
    A0[准备检查与 Work Contract] --> A1[直接阅读与模块地图]
    A1 --> A2[Gate A：边界、依赖、公共内容]
    A2 --> B0[后置结构校验]
    B0 --> B1[项目级入口页面与首个模块纵切片]
    B1 --> B2[Gate B：内容、UIUX、证据]
    B2 --> B3[依赖批次逐模块生成]
    B3 --> B4[模板、流程和模块质量复验]
    B4 --> B5[事实核对与适用维度]
    B5 --> B6[写入目标项目现实资料]
    B6 --> B7[完整资料对抗审查]
    B7 --> B8[独立验证与准入]
```

每个交接物都必须绑定上游摘要：`Work Contract → Module Map → Gate A → Semantic Package →
Gate B → Review Result`。任何摘要漂移、边界变化或返工都生成新摘要，不能覆盖旧记录。

## 阶段 A 的触发与退出

阶段 A 在以下条件同时满足后触发：

1. 准备检查通过；
2. 当前项目、基线、读取契约、来源角色和本轮用途已经锁定；
3. 模板包登记清单、方法论、适用页面和两个输出根已经确定；
4. 本轮静态材料读取已经获得授权。

模板包输入必须包含模板登记入口、模板包标识（或入口中的默认标识）、解析出的登记清单相对路径、
登记清单摘要和模板包摘要。默认登记入口是能力仓库根目录下的
`templates/reality-packs/registry.yaml`；登记清单所在目录是模板包目录，所有页面契约、方法论、
正向示例和审阅项都从登记清单声明的路径解析。

阶段 A 的唯一输入是上述范围信息、允许的一手材料和模板包。阶段 A 的输出是模块地图、语义
审阅包和 Gate A 记录。语义审阅包中的页面必须来自模板包声明的页面契约；阶段 A 不要求先运行
发现、盘点、候选图或其他自动生成工具。

阶段 A 开始时先读取模板包登记清单和方法论，再按本轮用途选择页面契约。页面契约决定页面
要回答的问题、可用来源角色、内容结构和审阅项；逆向工作流只决定什么时候消费它，不复制
或改写它。适用页面即使缺少证据也必须生成并标记未知或阻断；只有不适用页面才不生成。
登记清单、页面契约或来源真相无法确认时，阶段 A 直接阻断。

阶段 A 在以下任一情况停止：

- 用户尚未通过 Gate A 裁决模块、依赖、公共内容或未归类项；
- 用户要求扩大读取范围；
- 关键来源定位缺失；
- 发现范围、许可或基线冲突。

人工审阅如果要求拆分、合并或扩大读取范围，回到对应的前一步；不能在后续阶段静默改写
边界。

## 阶段 B 的内部顺序

阶段 B 也不是把所有参考文件全部执行一遍。按本轮用途选择：

1. 先做后置结构校验；
2. 物化模板包声明的项目级入口页面和第一个已接受模块的最小纵切片；
3. 由用户通过 Gate B，重点审阅内容丰富度、UIUX/前端、来源证据和 unknown/blocked；
4. 处理 Gate B 至多一次返工后，按照 Gate A 接受的依赖顺序逐模块生成语义包；
5. 按模板复验流程、页面消费和逐模块生成质量；
6. 处理复验问题后，再用调用链、数据结构、证据解释和按需维度补充事实；
7. 需要写入现实资料时，再做已审模块到目标项目业务域的映射；
8. 写入现实资料后，进行完整结果的对抗审查、独立验证和准入。

没有页面时跳过页面分析；没有相应事实维度时跳过对应分析；不适用的内容只在账本中记录状态。

## 阶段与最小产物

| 阶段 | 触发 | 负责内容 | 最小产物 | 不负责 |
| --- | --- | --- | --- | --- | --- |
| 准备 | 进入本能力后首先执行 | 锁定对象、基线、读取许可、用途和输出隔离 | 范围锁定记录 | 生成入口、模块或事实 |
| 阶段 A | 准备检查通过且已获静态读取授权 | 直接阅读、入口导航、模块地图、依赖顺序、语义组织和 Gate A | 入口与来源地图、Module Map、语义审阅包、Gate A 记录 | 事实核对、现实资料写入和准入 |
| 阶段 B | Gate A 已接受且没有范围阻断 | 后置校验、首个纵切片、Gate B、依赖批次生成、复验、事实核对、写入、验证和准入 | 问题项、项目级入口页面和模块页面、Gate B、逐模块包、中间复验、投影、验证与准入记录 | 静默改写边界或跳过人工门 |

## 输入顺序

1. 读取项目适配说明和读取契约；
2. 完成准备检查，形成并锁定 Work Contract；
3. 触发阶段 A，按入口形态选择辅助阅读步骤；
4. 由智能体直接阅读并形成 Module Map 与语义审阅包；
5. 由用户通过 Gate A 审阅模块边界、依赖、公共内容和未归类账本；
6. 只有 Gate A 接受后，才进入阶段 B 的后置结构校验；
7. 后置结构校验通过后，生成项目级入口页面和首个模块纵切片；
8. 由用户通过 Gate B 审阅内容、UIUX/前端和证据质量；
9. Gate B 通过后，按依赖批次逐模块生成其余语义包；
10. 按模板复验流程、页面和逐模块生成质量；
11. 中间复验问题处理完毕后，再补做事实核对；
12. 把成立事实写入目标项目自己的现实资料；
13. 对完整现实资料进行对抗审查；
14. 形成候选提交，交给独立验证方和准入入口。

## 工具边界

- 普通导航工具可以帮助定位已授权材料；
- 自动化工具不能决定模块、边界、公共内容、事实状态或业务归属；
- 后置校验只能输出问题项；
- Gate A 和 Gate B 各最多允许一次受控返工，人工不逐页代写；
- 模块生成只能消费已接受的依赖边和前序模块摘要；
- 项目级入口页面必须按模板包声明的 `target_path` 落到目标 Reality 根目录，不能创建未声明的输出容器；
- 模板、流程和逐模块质量复验由独立智能体按模板包完成；
- 提交准入脚本只检查提交、工作树状态、摘要、证据可见性和状态绑定，不能代替模板复验；
- 任何工具都不能把未知自动变成事实；
- 运行项目、网络调用或修改业务实现不属于本流程的默认动作。

## 必须停止的情况

- 目标项目或基线没有锁定；
- 读取范围存在冲突或未获许可；
- 输出目录不隔离；
- 没有稳定入口且没有明确记录未知；
- Gate A 尚未接受模块边界、依赖、公共内容和未归类项；
- 项目级入口页面和首个模块纵切片尚未通过 Gate B；
- 后置校验仍有阻断问题；
- 模板、流程或逐模块质量复验仍有 `rework_required` 或 `blocked`；
- 需要扩大读取范围但读取契约未修订；
- 无法让独立验证方检出同一候选提交。

## 不同项目形态

- 有页面：从页面、路由和用户操作进入；
- 纯服务：从接口资源、处理函数和请求响应结构进入；
- 异步系统：从任务、消费者、生产者和事件载荷进入；
- 命令行或开发工具：从命令、参数、输出和错误进入；
- 数据系统：从核心对象、结构和数据生命周期进入。

无论入口形态如何，模块边界都必须回到业务目标、对象、流程、状态、权限或接口责任，
不能退回技术目录。
