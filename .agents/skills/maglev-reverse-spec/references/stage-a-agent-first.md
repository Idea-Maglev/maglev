# 语义审阅：由智能体直接阅读一手材料

## 能力定位

这一部分负责把允许的一手静态材料整理成可供人审的语义模块草稿。它不直接写入目标项目
现实资料，也不依赖自动生成的模块候选。

它只做五件事：

1. 接收已经通过准备检查的范围、来源和模板输入；
2. 从稳定入口理解业务目标、实现和验证；
3. 按业务依据形成模块地图、依赖顺序、公共内容候选和未归类账本；
4. 按模板包组织语义审阅包和首轮页面适用性；
5. 把边界与依赖裁决交给用户。

它不负责重新做准备检查，不负责把入口地图自动变成模块，也不负责事实核对、现实资料写入或
独立准入。模块地图必须由直接阅读形成，不能由 scanner、inventory、候选图或目录统计推导。

## 触发条件

阶段 A 仅在以下条件同时满足后触发：

- `step-00-integrity-check.md` 已通过；
- 目标项目、基线、读取契约、来源角色和本轮用途已锁定；
- 模板包已选定；
- 人读产物与机器证据目录已隔离；
- 本轮静态材料读取已获授权。

阶段 A 的调用者是逆向现状重建工作流，不是入口地图、页面分析或后置校验文件单独触发。
如果上述条件不满足，返回准备阶段并记录缺口，不开始阅读业务材料。

## 输入（承接准备结果）

项目适配说明至少提供以下已经锁定的输入。模板登记入口相对能力仓库根目录解析，不相对目标项目
根目录解析：

```yaml
reverse:
  project_id: <项目标识>
  project_root: <项目相对路径>
  baseline: <基线提交>
  source_units:
    - unit_id: <来源单元>
      relative_path: <允许读取的相对路径>
      roles: [intent | implementation | verification]
      exclusions: []
  template_registry_path: templates/reality-packs/registry.yaml
  template_pack:
    pack_id: <模板包标识；缺省时必须由登记入口提供 default_pack_id>
    manifest_path: <由登记入口解析出的登记清单相对能力仓库根目录路径>
    manifest_digest: <登记清单摘要>
    pack_digest: <模板包摘要>
  output:
    human_review_root: <人读产物目录>
    machine_evidence_root: <机器证据目录>
    target_reality_root: <目标项目的 Reality 根目录>
  permissions:
    static_read: true
    runtime_read: false
    business_write: false
    reality_write: false
    project_execution: false
    material_reduction_tools: false
    script_execution: true
```

`script_execution: true` 只表示 Work Contract 可以在既有工作流声明的阶段执行已登记脚本；不表示
可以新增脚本、缩窄语义材料或把脚本输出当作模块/边界结论。阶段 A 仍不得运行未登记的语义
生成或材料缩窄脚本；不改变材料集合的既有确定性脚本只能在其声明阶段执行。

字段含义：

- `source_units` 是读取许可，不是模块列表；
- `roles` 是来源角色，不是模块归属；
- `template_registry_path` 是模板选择的唯一入口，默认值为 `templates/reality-packs/registry.yaml`；
  `template_pack.manifest_path` 必须由登记入口解析，不能由项目适配说明随意指定；
- `template_pack.manifest_path` 所在目录就是本轮模板包目录，模板路径相对该目录解析；
- 页面、方法论、正向示例和审阅项都必须从登记清单解析，不能直接遍历模板目录；
- `entry_hints`（如果宿主项目提供）只能提示阅读起点；
- 人读目录与机器证据目录必须互不包含。

多仓库或含子模块的项目，还要单独记录项目成员关系、基线和读取许可。成员关系不能替代
读取许可。

## 不能使用的输入

- 按目录、文件数量、词频或相似度生成的模块建议；
- 自动生成的候选图、候选清单或排序；
- 历史资料、失败产物或未授权来源；
- 运行时结果、网络调用和业务修复结果。

导航工具可以帮助找到已授权文件，但必须回到原文阅读。导航命中不等于业务事实。

## 阅读顺序

### 1. 找稳定入口

本节只负责为语义阅读选择起点。来源材料定位由
`step-01-evidence-acquisition.md` 提供，入口导航由 `step-01-project-map.md` 提供；
两者的结果在这里消费，不再重复建立一份入口清单。

- 有页面时，从页面、路由和用户操作开始；
- 没有页面时，从接口资源、任务、命令、软件开发工具包公开方法、事件或数据生命周期开始；
- 找不到稳定入口时记录 `[UNKNOWN]`，不以目录名替代。

每个入口记录相对路径、锚点、来源角色和证据状态。

入口需要深入确认时使用 `step-01b-router-analysis.md`；存在页面或用户交互时才使用
`step-02-page-analysis.md`。这些文件只补充入口事实，不另起模块流程。

### 2. 分开三类来源

围绕同一入口分别阅读：

1. `intent`：目标、用户任务、预期结果和约束；
2. `implementation`：页面、接口、代码、配置、数据和静态调用关系；
3. `verification`：测试对象、断言和已编码验证行为。

来源角色缺失时保留未知或阻断，不能用其他角色补齐。

### 3. 形成模块草稿

每个草稿至少说明：

- 业务目标或责任；
- 稳定入口；
- 与边界直接相关的最小实现线索；
- 与边界直接相关的对象和状态线索；
- 适用的接口、操作和验证；
- 事实、推断、未知和阻断；
- 相对路径证据。

阶段 A 只记录支撑语义和边界的最小线索，不展开完整调用链、数据结构、状态转换或运行行为；
这些内容在阶段 B 的事实核对中按用途补充。

模块可以跨来源单元。只由技术目录、仓库名、软件包名或类层级支撑的内容，不能单独成为
模块。

### 4. 形成模块地图和依赖顺序

模块地图是阶段 A 的核心交接，不是技术目录的改名。每个模块必须记录：

- 业务目标、责任和边界理由；
- 至少一个稳定入口和来源定位；
- 支撑边界的来源单元与来源角色；
- 适用的 Reality Slot；
- 关键 unknown、blocked 和下一处静态入口。

每条依赖边必须记录 `from`、`to`、`relation`、`order`、`evidence_refs` 和状态。`from` 与 `to`
分别是关系两端，`relation` 表示 `from` 对 `to` 的关系；`order` 只是待 Gate A 裁决的生成顺序，
不是由字段方向自动推导的排序。存在循环、缺少直接证据或无法确认方向时保留 `unknown`/`blocked`，
不能自动排序或删除边。

### 5. 记录公共内容和未归类内容

- 公共内容必须列出涉及的模块、直接依赖和证据；
- 无法归属的内容进入未归类账本；
- 角色冲突、入口不稳定和证据不足都要保留；
- 不创建默认“其他”模块。

## 模板包消费与人读审阅包

模板包是页面契约的唯一来源。阶段 A 不定义自己的页面清单或页面模板，只消费模板登记入口解析
出的模板包；适配说明只能在登记入口内明确指定模板包：

1. 读取 `template_registry_path`；使用登记入口的 `default_pack_id`，或使用本轮明确且已批准的模板
   包标识；两者都没有时直接阻断；
2. 从登记入口解析 `template_pack.manifest_path`，核对登记清单、模板包标识、登记清单摘要和
   模板包摘要；
3. 按登记清单的资产标识、公开路径和页面映射读取方法论、页面契约、正向示例和模板审阅项；
4. 读取方法论和采纳边界，确认页面结构的适用范围；
5. 读取 `materialization`，确认项目级入口页面按声明的 `target_path` 直接落到目标 Reality 根目录，
   不额外创建 manifest 未声明的输出容器；
6. 根据本轮用途、入口形态和可用证据，选择适用的项目级入口页面和模块页面契约；
7. 按选定页面的读者问题、来源角色、落地结构、正向示例和审阅项生成草稿；
8. 页面适用但证据不足时仍生成页面，明确标记 `[UNKNOWN]` 或 `[BLOCKED]`，写明缺失证据和
   下一步静态入口；不得用其他来源角色补齐；
9. 对不适用页面只记录 `not_applicable`、判断依据和落地位置，不创建空页面；
10. 模板资产缺失、登记清单与页面契约不一致或来源真相无法确认时停止并记录阻断；
11. 保留页面契约声明的页面标识和归属；不把页面契约改写成逆向专用的页面名称。

人读审阅包由两类内容组成：

- **模板页面草稿**：路径、页面标识和页面结构由模板包及目标项目资料契约决定；
- **流程记录**：范围、来源定位、边界审阅、公共内容、未归类项和后置问题的记录。

流程记录是执行凭据，不是另一套页面模板。公共内容和未归类项应放入模板包声明的适用页面
或边界审阅记录，不得借此新增平行的“模块清单”“来源定位页”或固定目录结构。人读内容
与机器证据仍须分离；机器证据只记录模板包摘要、选定页面、适用性、来源定位和审阅交接，
不重新定义页面。

页面适用性记录只保留模板包页面标识、适用状态、判断依据和落地位置四项，不新增页面注册表。

## Gate A：用户边界与依赖裁决

Gate A 审阅 `reverse_module_map` 和阶段 A 语义审阅包，至少裁决：

- 模块是否接受、拆分、合并、延期或保留未归类；
- 每条依赖边和生成顺序是否接受；
- 公共内容是否有真实跨模块依据；
- 关键 unknown、blocked 和读取范围是否需要升级。

Gate A 记录必须绑定 Work Contract 和模块地图；如果阶段 A 已形成语义包，也一并绑定其摘要，
并由人类给出结论。每个 Gate A 最多允许一次受控返工；返工只针对明确的边界、依赖或证据缺口，
不由人工逐页代写。

用户审阅模块边界、公共内容和未归类项，可作出：

- `accept`：接受当前边界或关系；
- `split`：按明确依据拆分；
- `merge`：证明真实跨模块关系后合并；
- `defer`：暂不裁决；
- `keep_unclassified`：保留未归类；
- `request_scope_change`：需要扩大读取范围，先修订读取契约。

接受的是语义草稿和边界，不是对现实事实的自动准入。

## 阶段 A 输出与退出

阶段 A 的完整输出是：

- 入口与来源地图；
- `reverse_module_map`：模块、边界依据、适用 Slot、依赖顺序、公共内容和未归类项；
- 一个或多个 `semantic_review_package`：按模块组织的页面适用性、Claim、SourceRef 和前序摘要；
- 公共内容和未归类账本；
- `reverse_gate_record`（Gate A）；
- 事实、推断、未知和阻断项。

只有用户已经裁决模块边界、依赖顺序、公共内容和未归类项，且读取范围、来源定位和关键断言
没有阻断，阶段 A 才结束并向阶段 B 交接。阶段 A 不生成现实资料投影，不执行事实准入。

## 进入阶段 B 的条件

只有同时满足以下条件，才能进入后置结构校验和事实核对：

- 读取范围和基线没有冲突；
- 模块边界已审；
- Gate A 已接受或明确交接为阻断；
- 依赖顺序已审，后续模块生成可以按批次执行；
- 公共内容和未归类项已有裁决；
- 每个关键断言都有来源角色和定位；
- 未知、阻断和缺少测试的地方没有被伪装成事实。
