# 人类可读输出契约

本契约适用于聊天、Markdown 文档和需要人类判断的非代码产物。仅明确标记为 `agent-only` 的内部文件可以不提供人类阅读面。

## 必须满足

1. 先说明读者需要理解、判断或完成什么，再组织内容；不得要求读者从机器状态或内部编号反推含义。
2. 英文术语、缩写和符号首次出现时提供中文解释或可访问的定义链接；代码、路径和 API 原名可以保留。
3. 机器配置格式（YAML、JSON）需要人类判断时，必须提供可追溯的 Markdown 映射；人不需要审核机器文件。
4. 流程、状态、关系、依赖和时序适合图示时使用 Mermaid；图必须服务理解，不为满足形式而添加。
5. 事实、推断、未知和阻断必须清楚区分；机械检查通过不能表述为内容质量通过或人类接受。
6. 对外能力文件只描述当前有效行为和边界，不混入会话过程、迁移叙事或作者取舍。

## 开放结构

本契约不规定标题、章节、段落顺序、页数、篇幅、词句、页面类型或固定图形。内容结构和深度由读者任务、事实复杂度和证据密度决定。

## 验证边界

确定性检查只验证路径、格式、摘要、链接和映射等可复算事实；自然语言是否清楚、内容是否充分、图表是否合适由语义审查和人类判断负责。
