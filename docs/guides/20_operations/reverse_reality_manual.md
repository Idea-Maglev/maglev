# 逆向现状重建使用手册

这份手册面向项目负责人、接手者和验证者。它说明如何把逆向现状重建能力用于任意真实项目，
不预先规定项目模块，也不要求项目采用某一种技术栈。

本文只规定流程步骤。质量不来自流程走完——人的关键判断点、成本投入档位与问题校准动作
见[逆向质量判断指南](reverse_quality_judgment_guide.md)，两份文档配合使用。

## 先看阶段怎么触发

| 阶段 | 触发条件 | 负责内容 | 交付 |
| --- | --- | --- | --- |
| 准备 | 用户提出逆向现状重建请求 | 锁定项目、基线、读取许可、用途和输出位置 | 范围锁定记录 |
| 阶段 A：语义审阅 | 准备检查通过，且静态材料读取已获授权 | 直接阅读、形成语义模块草稿、人工审阅边界 | 语义审阅包和边界审阅记录 |
| 阶段 B：事实核对与准入 | 阶段 A 的边界已裁决，且没有范围阻断 | 后置校验、模板/流程/模块质量复验、事实核对、现实资料写入、独立验证和准入 | 中间复验记录、现实资料投影、验证和准入记录 |

阶段 A 不是单独再运行一套扫描或发现流程；本手册第三至第五节属于阶段 A。阶段 B 从第六节
开始。阶段 A 未结束时，不执行阶段 B 的内容。

实际使用时，先提出“为这个已有项目重建当前现状”之类的请求，由入口路由交给逆向现状重建
能力；能力完成准备检查后，才开始阶段 A。只打开某个步骤文件，或只运行某个辅助分析步骤，
都不会单独启动阶段 A。

## 准备阶段：一、开始前准备

由项目负责人或调用方提供：

1. 目标项目根目录；
2. 本轮基线提交；
3. 本轮用途，例如交接、重构前分析、接口核对或验证；
4. 允许读取的来源目录、文件或仓库；
5. 每个来源的角色：
   - `intent`：目标、用户任务、产品约束；
   - `implementation`：页面、路由、接口、代码、配置、数据结构；
   - `verification`：测试、断言和已编码验证行为；
6. 目标项目自己的现实资料位置和资料契约（如果已有）；
7. 可使用的模板包；
8. 人读产物目录和机器证据目录，且二者不能互相包含。

模板包先由 `template_registry_path` 登记入口解析；该路径相对能力仓库根目录，不相对目标项目根目录。
适配说明只能在登记入口内明确指定模板包。`manifest_path` 所在目录就是模板包目录。开始阶段 A
前，先读取该登记清单中标记为来源真相的资产，
再读取方法论、页面契约、正向示例和模板审阅项；不能按目录名、历史产物或逆向能力自己的
页面清单选择模板。当前仓库提供的模板资产位于 `templates/reality-packs/`，但其他项目可以
使用适配说明指定的其他模板包。

准备阶段只锁定“可以读什么”和“要交付什么”，不先列模块。

## 准备阶段：二、建立读取契约

为目标项目建立一份最小读取契约。它可以是项目自己的配置文件，也可以是本次会话中的结构化
输入，但必须能回查：

```yaml
reverse:
  project_id: <项目标识>
  project_root: <项目相对路径>
  baseline: <基线提交>
  source_units:
    - unit_id: product-material
      relative_path: docs/product
      roles: [intent]
      exclusions: []
    - unit_id: application
      relative_path: src
      roles: [implementation]
      exclusions: []
    - unit_id: tests
      relative_path: tests
      roles: [verification]
      exclusions: []
  template_registry_path: templates/reality-packs/registry.yaml
  template_pack:
    pack_id: <模板包标识；缺省时必须由登记入口提供 default_pack_id>
    manifest_path: <由登记入口解析出的登记清单相对路径>
    manifest_digest: <登记清单摘要>
    digest: <模板包摘要>
  output:
    human_review_root: <项目外或隔离的人读目录>
    machine_evidence_root: <项目外或隔离的机器证据目录>
```

契约中的路径是读取许可，不是业务模块列表。若项目由多个仓库、子模块或软件包组成，还要为
每个成员记录项目清单依据和基线；项目成员关系不能替代读取许可。

范围存在冲突、来源未获许可或输出目录不隔离时，先停在准备阶段，不能继续阅读。

## 阶段 A：三、直接阅读并建立入口地图

按以下顺序在允许范围内阅读：

1. 先找页面、路由和用户操作；
2. 没有页面时找接口资源、命令、任务、事件或软件开发工具包公开方法；
3. 如果仍没有稳定入口，再从核心数据对象和数据生命周期进入；
4. 同时回查与入口直接相关的需求材料和测试；
5. 为每个入口记录相对路径、锚点、来源角色和证据状态。

入口类型只是阅读起点：

| 项目形态 | 优先入口 |
| --- | --- |
| 有页面的应用 | 页面、路由、用户操作 |
| 接口服务 | 接口资源、处理函数、请求和响应结构 |
| 异步系统 | 任务、消费者、生产者、事件载荷 |
| 命令行或开发工具 | 命令、子命令、参数、输出 |
| 数据系统 | 实体、表、模式、数据生命周期 |

入口地图用于导航，不是模块清单。找不到入口时登记未知，不用目录名或文件数量替代。

## 阶段 A：四、生成语义审阅包

智能体围绕每个稳定入口直接阅读原文，按模板包生成可读草稿。每个模块至少回答：

- 它服务的目标或业务责任是什么；
- 由什么页面、接口、任务、命令、事件或数据对象进入；
- 与边界直接相关的最小实现线索；
- 与边界直接相关的对象和状态线索；
- 哪些内容由需求材料支持；
- 哪些内容由代码和配置支持；
- 哪些内容由测试支持；
- 还缺哪些证据。

阶段 A 不要求完成完整调用链、数据结构、状态转换或运行行为；这些内容在阶段 B 按本轮用途
补充，避免两阶段重复产出同一份事实资料。

语义草稿要把三类来源分开：

| 来源角色 | 可以说明 | 不能说明 |
| --- | --- | --- |
| `intent` | 目标、用户任务、产品结果和约束 | 当前实现是否生效 |
| `implementation` | 页面、接口、代码、配置、数据和静态调用关系 | 用户目标是否成立 |
| `verification` | 测试对象、断言和已编码验证行为 | 生产行为一定成立 |

草稿中的结论使用 `[FACT]`、`[INFERENCE]`、`[UNKNOWN]`、`[BLOCKED]` 标记。没有直接证据
就不能写成事实。

### 模板包如何被实际使用

阶段 A 不能按自己的目录或文件清单写稿，必须先消费模板包：

| 模板包内容 | 阶段 A 的用法 | 不能做什么 |
| --- | --- | --- |
| 登记清单 | 核对模板包标识、摘要、公开页面和页面归属 | 自己枚举目录或选择未登记页面 |
| 方法论与采纳边界 | 判断页面结构适合回答什么问题 | 把外部方法直接变成项目事实 |
| 页面契约 | 按读者问题、来源角色和落地结构写入适用页面 | 自定义另一套页面字段或目录 |
| 正向示例 | 学习表达深度和证据写法 | 复制示例中的项目事实 |
| 模板审阅项 | 在提交人工审阅前逐页自查 | 用审阅项自动决定模块边界 |

阶段 A 只选择本轮适用的项目级入口页面、能力页面和证据页面；实现、接口、运行和验证页面在阶段 B
按事实维度账本继续填写。每个页面保留模板包声明的页面标识和归属，不能改造成逆向专用页面。

页面已判定适用但证据不足时，仍按页面契约生成，并将缺口标为 `[UNKNOWN]` 或 `[BLOCKED]`，
写明缺失来源和下一步静态入口；页面不适用时才不生成页面，只记录 `not_applicable` 及其依据。

人读审阅包的页面路径、页面标识和目录层级由模板包与目标项目资料契约共同决定，不固定为：

```text
总入口页 / 模块清单 / 模块目录 / 来源定位页
```

公共内容、未归类项和边界裁决属于流程记录，应放在模板包声明的适用页面或单独的审阅记录中，
不能借此再造一套页面模板。人读内容只放可读资料；模板包摘要、页面适用性、来源定位和校验
记录放在独立机器证据目录。

页面适用性只需记录四项：模板包声明的页面标识、是否适用、判断依据和落地位置。它是本轮
消费模板包的执行记录，不是新增的页面目录或模板注册表。

## 阶段 A：五、人工审阅边界

用户只需要审阅四件事：

1. 模块是否代表独立的业务目标、对象、流程、状态或接口责任；
2. 哪些内容必须拆开或合并；
3. 哪些内容确实是跨模块公共内容；
4. 哪些内容暂时无法归属或缺少证据。

可用裁决：

- `accept`：接受当前边界；
- `split`：要求拆分并说明依据；
- `merge`：只有存在真实跨模块关系时合并；
- `defer`：暂不裁决，保持未决；
- `keep_unclassified`：明确保留未归类；
- `request_scope_change`：需要扩大读取范围，先修订契约。

边界未裁决前，不进入事实核对，不写入目标项目现实资料。

## 阶段 B：六、后置结构校验

人工审阅完成后，才可以进行只读结构校验。校验只检查：

- 读取契约是否匹配；
- 来源路径和锚点是否可回查；
- 三类来源角色是否越界；
- 模板页面和必需区块是否齐全；
- 人读目录和机器证据目录是否隔离；
- 相对链接是否有效；
- 未知、阻断和未归类项是否被保留。

这里检查的页面和必需区块必须来自本轮模板包登记清单及页面契约，不能使用逆向能力另列的页面
清单作为标准。

校验输出称为“问题项”，每条问题项都要写明位置、观察到的证据、违反的约束、负责处理者和
下一步回到哪里。校验不能重命名模块、自动拆分合并、增加公共内容或改写语义。

问题项处理方式：

- 影响范围或读取许可：回到契约准备；
- 影响模块边界或语义归属：回到智能体阅读并重新人工审阅；
- 影响路径、结构或链接：修订审阅包后重新校验；
- 证据缺失：保留未知或阻断，不补写结论。

阻断问题清零，或用户明确接受剩余非阻断问题后，才能继续。

### 阶段 B：六（续）、模板、流程和模块质量复验

后置结构校验通过后，先按同一模板包进行中间复验，再进入事实核对。复验者必须重新读取：

1. 模板登记入口和登记清单；
2. 本轮实际使用的方法论、页面契约、正向示例和模板审阅项；
3. 阶段 A 语义审阅包、边界裁决、公共内容和未归类账本；
4. 后置结构校验问题项及处理结果。

复验分四组：

- **流程**：是否先直接阅读、再形成语义草稿、再人工裁决边界；是否没有用脚本、目录或候选图决定模块；
- **模板**：页面是否来自登记清单，是否回答专属读者问题，是否使用正确来源角色，是否正确处理适用、
  `unknown`、`blocked` 和 `not_applicable`；
- **模块**：每个模块是否有独立目标、稳定入口、边界依据、三类来源分离、证据和继续深挖路径；
- **跨模块**：公共内容是否有真实依赖，无法归属内容是否进入未归类账本，是否存在越级归属。

每个模块都必须单独给出“可继续、需返工或阻断”结论，不用模块数量、文件数量或总分代替判断。
模板、流程或任一模块存在未处理的返工/阻断问题时，不得进入事实核对。

复验记录属于流程证据，不是新的 Reality 页面，也不由提交准入脚本生成。

## 阶段 B：七、事实核对与适用维度

只消费已经接受的模块和当前来源，不重新生成模块。根据项目入口和本轮用途核对：

事实核对应继续填写模板包中与本轮适用维度对应的页面契约；不另建调用链、数据结构或验证
页面来平行承载同一事实。

- 入口、流程和结果；
- 调用链和依赖方向；
- 数据结构、字段约束和生命周期；
- 状态、转换、失败和补偿；
- 接口、事件、命令或软件开发工具包约定；
- 权限、配置、运行行为和验证证据（仅在适用且有材料时）。

每个维度都登记为：

- `covered`：当前用途所需事实已有可回查证据；
- `not_applicable`：有依据确认本轮不适用；
- `unknown`：适用但证据不足；
- `blocked`：因许可、访问、基线或外部条件无法继续。

不为不存在的维度创建空页面，也不以扫描数量代替完整性。

## 阶段 B：八、写入目标项目现实资料

如果目标项目已有资料契约：

1. 读取目标项目自己的资料入口和业务域登记；
2. 将已核对事实映射到目标项目规定的业务域和资料位置；
3. 保留既有事实，避免覆盖未经核对的内容；
4. 把未知、阻断和证据边界写清楚；
5. 不把分析模块名或技术来源名直接当成业务域名。

如果目标项目还没有资料契约，应在同一候选提交中建立它自己的最小入口和首批事实资料。不能
复制 Maglev 自身的业务域、资料页或项目事实。

逆向只修改现实资料，不修改业务代码、测试、数据或接口实现。

## 阶段 B：九、独立验证与准入

写入现实资料后，必须形成可检出的候选提交，并记录：

- `base_commit`：修改前基线；
- `candidate_commit`：含本次现实资料的提交；
- 完整现实资料摘要；
- 本次变化摘要；
- 本轮用途。

独立验证方必须检出同一候选提交，读取完整现实资料和本次变化，并核对：

- 是否使用了同一模板登记入口、模板包和中间复验记录；
- 流程是否遵守边界裁决、事实核对、写入和验证的顺序；
- 每个页面是否符合页面契约并正确处理适用性和来源角色；
- 每个模块是否有可解释的目标、入口、边界、证据和缺口；
- 每条事实是否有已提交且可定位的证据；
- 推断是否仍标为推断；
- 未知和阻断是否保留；
- 既有资料与新增资料是否冲突、重复或失效；
- 本轮是否误改业务实现；
- 结果是否满足本轮用途。

准入脚本只检查提交、工作树状态、摘要、证据可见性和验证结果绑定，不能代替上述模板和模块复验。
准入只确认已经独立验证的候选提交，不重新写入资料。只有收到 `accepted` 或 `no_change`，才能
收口；否则交付阻断原因和下一责任点。

## 阶段 B：十、交付检查

交付前逐项确认：

- [ ] 读取范围、基线和输出隔离有证据；
- [ ] 稳定入口来自直接阅读，而不是自动生成的候选；
- [ ] 模块边界经过人工审阅；
- [ ] 目标意图、当前实现和验证依据没有互相替代；
- [ ] 公共内容有真实跨模块依赖；
- [ ] 无法归属的内容进入未归类账本；
- [ ] 后置校验只产出问题项；
- [ ] 模板、流程和逐模块质量复验已完成，且没有未处理的返工或阻断问题；
- [ ] 事实核对只消费已接受边界；
- [ ] 现实资料中的关键事实都有相对路径证据；
- [ ] 现实资料写入目标项目自己的位置；
- [ ] 业务代码、测试、数据和运行状态没有被逆向过程改变；
- [ ] 独立验证和准入结果已绑定同一候选提交。

任何一项无法满足，都应明确交付阻断交接，不应使用“基本完成”替代证据。
