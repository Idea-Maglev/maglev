# 软件研发项目 Wiki 推导指南

本指南帮助 Agent 阅读软件项目事实，不是默认目标清单，也不规定 Wiki 页面数量或目录结构。

## 约束

- 先读取项目 Reality、架构、接口、运行、验证和用户材料，再提出结构；
- 只纳入有来源支持且对目标读者有价值的内容；
- 无证据或不适用的方向可以不生成页面，但要在结构方案中解释；
- 结构方案必须在人类批准后才能进入正文写作。

## 建议观察面

按项目实际情况判断，不要求全部采用：

- 项目解决的问题、目标用户和责任边界；
- 核心能力、业务流程与失败路径；
- 技术架构、接口、数据、配置和依赖；
- 安装、首次成功、常见任务、排障和交付；
- 质量、安全、权限、已知风险与未证实行为；
- 采用条件、设计权衡、变更影响和贡献方式。

先判断哪些读者需要哪些答案，再决定维度、方面和页面。一个页面可以回答多个相关问题；一个高风险问题也可以拆成多页。

## 示例边界

上述观察面只是防止遗漏的思考提示，不是内容配额。项目可以只生成少量页面，也可以形成更细的页面树。

**不要复制本页的条目数量、顺序或篇幅。** 合适的内容量由项目复杂度、读者任务、证据密度和更新频率决定。
